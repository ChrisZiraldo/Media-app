Foundation

Five principles shape every screen.

The interface prioritizes recognition and confidence. Discovery supports the collection instead of competing with it.

01

Private by default

No public profiles, social layer, or accidental public exposure.

02

Explicit state

Every add, status change, episode check, and removal is intentional.

03

Library first

The collection is the default destination; search is a focused supporting tool.

04

Clear recovery

Pending and failed actions preserve context and always offer a way forward.

05

Useful density

Artwork aids recognition while status and progress remain easy to scan.

Primary loop

Find. Place. Progress.

Three verbs cover the recurring workflow: find a title, place it in the right status, and record progress without inference.

01 · FindSearch movies, television, or both after two meaningful characters.
→
02 · PlaceAdd once to Watchlist, Watching, Watched, or Dropped.
→
03 · ProgressRecord explicit movie status or individual episode history.

System boundary

One service, two interfaces, no leaked secrets.

The browser and Hermes share domain behavior through MediaService. SQLite owns personal state; TMDB enriches the catalog.

Tailnet browserSame-origin React client under /media/
→
Tailscale ServePrivate HTTPS; strips the public path prefix
→
Fastify + MediaServiceValidated HTTP and shared domain rules on 127.0.0.1:3460
↙
SQLiteCanonical library, status, notes, and episode records
↘
TMDBServer-side catalog enrichment only
Browser boundary

React calls only same-origin /api/v1 routes. No TMDB key or direct catalog calls.

MCP boundary

Hermes invokes the same MediaService and requires confirm: true for removal.

Data boundary

Personal state stays local. Raw TMDB JSON, search history, and image files are not stored.

Network boundary

Loopback listener, Tailnet ingress only, no Funnel, and existing Serve routes remain intact.

Domain invariants

Rules the interface must communicate.

These behaviors are not presentation choices; they are shared product guarantees across HTTP and Hermes.

ID

No duplicate title

TMDB ID plus media type identifies one catalog title.

TV

Derived progress

Episode rows determine progress; no second mutable counter exists.

✓

Explicit completion

Checking the final episode never silently marks a series Watched.

↻

Safe retry

Episode actions and repeat additions remain idempotent.

!

Confirmed removal

Destructive deletion always names the title and requires confirmation.
